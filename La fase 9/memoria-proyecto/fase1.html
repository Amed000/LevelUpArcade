FASE 1 – ANÁLISIS DEL SISTEMA
1. Descripción del sistema
El sistema que se va a desarrollar es una aplicación de gestión para la empresa LevelUp
Arcade, especializada en la venta de videojuegos y merchandising.
Actualmente la empresa gestiona su información mediante hojas de cálculo, lo que
provoca errores, duplicidad de datos y pérdida de control del inventario y clientes.
El objetivo del sistema es crear una aplicación en Java conectada a una base de datos
MySQL que permita gestionar de forma centralizada:
• Productos
• Clientes
• Proveedores
Además, incorporará funcionalidades de Inteligencia Artificial mediante OpenRouter
para mejorar la gestión de productos.

2. Objetivos del sistema
• Digitalizar la gestión de inventario.
• Mejorar la gestión de clientes y proveedores.
• Reducir errores humanos.
• Automatizar tareas mediante IA.
• Centralizar toda la información en una base de datos.
• Facilitar el mantenimiento y escalabilidad del sistema.

3. Requisitos funcionales
Los requisitos funcionales describen qué hará el sistema.
RF1. Gestión de usuarios
El sistema permitirá registrar, modificar, eliminar y consultar usuarios.
RF2. Gestión de clientes
El sistema permitirá almacenar la información de los clientes, incluyendo nombre,
teléfono y correo electrónico.
RF3. Gestión de productos
El sistema permitirá registrar videojuegos, consolas y accesorios con su precio, stock y
categoría.
RF4. Gestión de proveedores
El sistema permitirá almacenar y administrar la información de los proveedores.
RF5. Gestión de pedidos
El sistema permitirá crear pedidos asociados a clientes y productos.
RF6. Control de stock
El sistema actualizará automáticamente el stock de productos después de cada venta o
pedido.
RF7. Búsqueda de información
El sistema permitirá buscar productos, clientes y pedidos mediante filtros.
RF8. Conexión con base de datos
El sistema almacenará toda la información en una base de datos MySQL/MariaDB.
RF9. Inicio de sesión
El sistema permitirá iniciar sesión mediante usuario y contraseña.
RF10. Generación de informes
El sistema permitirá consultar listados de productos, clientes y pedidos.

4. Requisitos no funcionales
1) Requisitos de capacidad
• El sistema deberá soportar al menos 50 productos registrados.
• El tiempo de respuesta de las consultas no deberá superar los 3 segundos.
• La base de datos deberá permitir almacenar clientes, pedidos y productos sin
pérdida de rendimiento.
2) Requisitos de interfaces
• El sistema se conectará a una base de datos MariaDB/MySQL mediante JDBC.
• El sistema será desarrollado en Java usando Eclipse.
• La interfaz utilizará formularios gráficos básicos.
3) Requisitos de operación
• El sistema deberá permitir iniciar y cerrar sesión.
• El usuario podrá utilizar teclado y ratón para navegar.
• El sistema deberá poder iniciarse desde cualquier ordenador con Java instalado.
4) Requisitos de recursos
• Se necesitará un servidor Ubuntu con MariaDB instalado.
• El sistema requerirá Java JDK y el conector JDBC de MySQL.
• Se necesitará conexión en red para acceder a la base de datos remota.
5) Requisitos de verificación
• El sistema deberá comprobar que los campos obligatorios estén completos.
• El sistema validará usuarios y contraseñas antes del acceso.
6) Requisitos de pruebas de aceptación
• El sistema será aceptado si permite gestionar correctamente productos, clientes y
pedidos.
• Todas las operaciones CRUD deberán funcionar correctamente.
7) Requisitos de documentación
• El proyecto incluirá documentación técnica y manual de usuario.
• Se entregarán diagramas UML y scripts SQL.

8) Requisitos de seguridad
• El acceso al sistema requerirá autenticación mediante contraseña.
• Solo los usuarios autorizados podrán modificar datos.
• La base de datos estará protegida mediante usuarios y permisos.

9) Requisitos de transportabilidad
• El sistema podrá ejecutarse en Windows y Linux.
• La aplicación podrá trasladarse fácilmente usando Java.

10) Requisitos de calidad
• La interfaz deberá ser sencilla e intuitiva.
• El código seguirá una estructura MVC para facilitar la organización.

11) Requisitos de fiabilidad
• El sistema deberá mantener la información almacenada sin pérdidas.
• La aplicación deberá minimizar errores durante el uso normal.

12) Requisitos de mantenibilidad
• El código estará dividido en clases y paquetes organizados.
• La estructura permitirá añadir nuevas funciones fácilmente.

13) Requisitos de salvaguarda
• El sistema deberá evitar eliminar información accidentalmente.
• Se realizarán copias de seguridad de la base de datos.

5. Actores del sistema
Administrador
• Acceso total al sistema.
• Puede crear, modificar y eliminar cualquier dato.
• Gestiona usuarios.
Empleado
• Puede consultar datos.
• No puede modificar ni eliminar información.
• Acceso limitado a funcionalidades.

7. Historias de usuario
HU1 – Gestión de productos
Como administrador, quiero poder añadir, modificar y eliminar productos para mantener
actualizado el inventario.
HU2 – Consulta de datos
Como empleado, quiero consultar productos, clientes y proveedores para atender a los
clientes.
HU3 – Gestión de clientes
Como administrador, quiero gestionar clientes para mantener la base de datos
actualizada.
HU4 – Gestión de proveedores
Como administrador, quiero gestionar proveedores para controlar el abastecimiento.
HU5 – IA para productos
Como administrador, quiero generar descripciones automáticas para ahorrar tiempo.

Decisiones

Decisiones técnicas tomadas

  • Se plantea una aplicacion Java conectada a MySQL/MariaDB para centralizar la informacion.
  • Se separan perfiles de Administrador y Empleado para controlar permisos desde el inicio.
  • Se incluyen funciones de IA con OpenRouter para automatizar descripciones y categorias.
  • El sistema queda orientado a operaciones CRUD sobre productos, clientes, proveedores y pedidos.
